## 0. ГЛАВНОЕ ЗА ОДНУ МИНУТУ

**Что это.** «ФРОНТИР» — браузерная стратегия про развитие цивилизации от
первого костра до Шпиля, уходящего в звёзды. 10 эпох, 62 технологии,
58 зданий, 8 фракций-соседей с ИИ, дипломатия, рынок, рейды, события.

**Как запускается.** Двойной клик по `frontier.html`. Один файл, работает
офлайн по `file://`, без сети, сборщиков и фреймворков. На телефоне — тот же
файл, интерфейс сам переключается в мобильный режим.

**Чем НЕ является.** Это не Unity и не Unreal. Предыдущее ТЗ (№5) требовало
Unity-проект — решение было пересмотрено заказчиком в пользу браузера, потому
что браузерный билд запускается у заказчика прямо сейчас, а Unity-проект
потребовал бы установки движка и не мог быть проверен исполнением.
**Не переписывай на другой движок без прямого указания заказчика.**

**Язык.** Весь интерфейс, все тексты, все комментарии в коде — русские.
Английские строки в интерфейсе недопустимы.

## 1. КАК ЗАПУСКАТЬ И ПРОВЕРЯТЬ

```bash
# из корня репозитория. Node 22, ничего кроме esbuild ставить не нужно.

npm install                     # только esbuild, для сборки одного файла

# --- тесты: 96 штук в шести файлах, ВСЕ должны быть зелёными ---
node app/tests/simtest.mjs          # 18 — ядро
node app/tests/test-borders.mjs     # 17 — границы (U01-U04)
node app/tests/test-population.mjs  # 13 — население (U05,U06,U09,U10)
node app/tests/test-winter.mjs      # 13 — зима (U07)
node app/tests/test-production.mjs  # 24 — производство и торговля (U11,U17)
node app/tests/test-market.mjs      # 11 — экран рынка (U16)

# --- сборка и визуальная проверка ---
node tools/build.mjs            # пересобрать frontier.html из app/ (esbuild)
node tools/shot.mjs             # скриншоты в настоящем Chromium + ловля ошибок консоли
node tools/shot.mjs town        # только один пресет

# --- арт ---
node tools/art/gen-prompts.mjs  # пересобрать список промтов на генерацию
node tools/art/cutout.mjs       # вырезать фон: art/raw/*.png → app/assets/sprites/

# --- сборка архива передачи ---
node tools/pack.mjs             # ФРОНТИР_передача.zip со всем проектом
```

Playwright для `shot.mjs` берётся глобальный: если его нет, поставь
`npm i -g playwright` или пропусти этот шаг — на тесты ядра он не влияет.

**Правило приёмки:** после любой правки прогоняй `simtest.mjs` и `shot.mjs`.
`shot.mjs` возвращает ненулевой код, если в консоли браузера есть хоть одна
красная ошибка. Ноль ошибок — обязательное условие.

`tools/shot.mjs` умеет строить настоящий город из 33 построек (`town`,
`town_night`, `town_phone`) — без этого на скриншотах пустая карта и оценить
отрисовку невозможно.

Мир задаётся сидом через адрес: `app/index.html#seed=4242`. Один сид — один
мир. Удобно и для игрока, и для повторения баг-репортов.

## 2. АРХИТЕКТУРА

```
app/
  index.html              разметка + CSS. Все id, к которым обращается код (их 47).
  src/
    core/                 ЯДРО. Чистый JS, никакого DOM. Тестируется в node.
      simulation.js       класс Simulation (~1900 строк): тик, экономика, жители,
                          армия, рейды, фракции, дипломатия, рынок, события, сейв
      data.js             ВСЕ таблицы: TILE, RES, ERAS, TECHS, BUILDINGS, UNITS,
                          COUNTERS, FACTIONS, DIPLO_FACTORS, WEATHER, EVENT_DEFS
      world.js            генерация мира, A*, stepToward, findNearestTile
      rng.js              детерминированный ГПСЧ + шум Перлина
      systems/            новые подсистемы улучшений (см. §5)
    render/               ОТРИСОВКА. Ядро о ней не знает.
      renderer.js         оркестратор кадра
      terrain.js          местность: рельефный свет, биомы, детали, берег
      sprites.js          процедурные спрайты построек, 22 архетипа силуэтов
      palette.js          цветовая библия: местность, эпохи, свет по времени суток
      quality.js          пресеты графики + автоподбор по FPS
      artpack.js          подмена процедурных спрайтов нарисованным артом
    ui/
      hud.js              весь DOM-интерфейс: панели, модалки, вкладки
      audio.js            WebAudio: синтезированные SFX + музыка
      assets.js           сгенерированные ассеты в data-URI (обложка, победа, тема)
    save/saveSystem.js    localStorage + экспорт/импорт файлом
  tests/simtest.mjs       18 headless-тестов
tools/
  build.mjs               сборка однофайлового frontier.html
  shot.mjs                скриншоты в Chromium + проверка консоли
  art/                    конвейер нарисованного арта (см. §6)
```

**Разделение слоёв железное:** ядро не знает про DOM и canvas. Это позволяет
гонять всю математику в node и держать 18 тестов. Не ломай это.

**Детерминизм.** Вся случайность идёт через `this.rng` (mulberry32 от сида).
`Math.random` в игровом коде запрещён: он ломает воспроизводимость мира и
сейвы. Это не стиль, а требование — есть тест на детерминизм.

## 4. ЧТО ЗАВЕДОМО НЕ РАБОТАЕТ (честный список)

Проверено по коду, не догадки:

- **Армия не рисуется на карте.** `renderer.js` не содержит ни одного
  упоминания UNITS. Армия — число во вкладке «Армия».
- **Контр-цикл родов войск не работает.** Таблица `COUNTERS` в `data.js`
  есть, в расчёте боя не участвует.
- **Интерфейс рынка написан, но НЕ ПОДКЛЮЧЕН.** Модуль `ui/panel_market.js`
  готов и покрыт 11 тестами, однако в `hud.js` вкладки рынка пока нет —
  в игре кнопки «продать» по-прежнему не существует. Подключить: добавить
  запись в массив `TABS` и метод `panel_market()`, вызывающий модуль.
- **Аура кузницы «+10% соседям» не применяется**, приоритет труда «Стройка»
  ни на что не влияет.
- **Сейв теряет** мирные пакты, штрафы событий, кулдаун событий — возможен
  сейв-скам и потеря купленного мира.
- **Робозавод** (`workers: 0`) не производит ничего: отсекается проверкой
  `!def.workers`. Одно из самых дорогих зданий игры — декорация.
- **Погода у фермы умножается дважды**: дождь вместо +15% даёт −2%.
- **Кризис еды** при населении 57+ без амбаров становится вечным: порог
  `население × 0.7 × 5` превышает потолок склада 200.
- Нет экранов достижений и мировой карты (в мануале они есть — в игре нет).

## 6. АРТ: КОНВЕЙЕР И СОСТОЯНИЕ

Игра умеет рисовать здания двумя способами и **переключается автоматически**:
если для здания есть нарисованный спрайт — берётся он, если нет — рисуется
процедурно. Поэтому арт можно подвозить по частям.

```bash
node tools/art/gen-prompts.mjs   # пересобрать список промтов
node tools/art/cutout.mjs        # вырезать фон у art/raw/*.png → app/assets/sprites/
```

**Как устроено вырезание.** Генератор рисует объект на магентовом фоне
(`#FF00FF` — хромакей). `cutout.mjs` ищет фон **по тону**, а не по точному
цвету (генератор часто выдаёт малиновый градиент), удаляет только пиксели,
**связанные с краем кадра** (иначе вырезало бы розовые детали внутри самой
постройки), смягчает контур и обрезает по субъекту. Файлы, где в кадре
нарисованы трава/небо/солнце, помечаются как требующие перегенерации —
их нельзя «починить», нужно снять заново.

**Ловушка, на которой уже обожглись:** формулировка «single warm sun from the
top-left» заставляла модель рисовать **настоящее солнце в кадре**, а под
постройку подкладывать магентовый ромб на траве. В промтах это исправлено:
источник света явно запрещён в кадре, подставки перечислены поимённо.

**Состояние:** сгенерировано 41 изображение (все — здания), из них 15 новым
промтом. Осталось по приоритету 109. Приоритеты выставлены по тому, что игра
**реально отрисовывает**: 15 промтов помечены «генерировать не надо», потому
что применить их негде (юниты не рисуются, экранов достижений и мировой карты
не существует).

## 6-Б. ЗАДАНИЕ НА АНИМАЦИЮ (Kimi Video Generator)

Заказчик хочет, чтобы город перестал быть картинкой и стал живым. Начинать
**с современных эпох** (индустриальная и дальше) — там движения больше всего
и эффект заметнее, а каменный век обойдётся дымком над костром.

### Как анимация попадает в игру

Игра рисует спрайты на canvas. Видео как таковое в игру не вставляется —
из ролика **нарезаются кадры спрайт-листа**. Формат: горизонтальная лента
кадров, прозрачный фон, тот же хромакей `#FF00FF`, что и у статики.
8–12 кадров на цикл при 8–12 кадрах в секунду — этого достаточно, чтобы
движение читалось, и мало, чтобы не раздуть вес.

**Критично:** здание между кадрами НЕ должно смещаться, менять масштаб,
ракурс или освещение. Двигаются только те части, что перечислены. Камера
неподвижна абсолютно. Любой дрейф камеры превращает анимацию в дёрганье.

### Шаблон промта для видео

```
Seamless looping animation of a single game building asset.
The camera is completely static — no pan, no zoom, no parallax, no drift.
The building itself does not move, rotate, rescale or change lighting.
Only the elements listed below move. Loop must be perfect: last frame
matches first frame exactly.

Style: hand-painted 2.5D strategy-game asset art, semi-realistic historical,
elevated three-quarter top-down view tilted about 65 degrees from vertical.
Warm daylight from the upper left at 45 degrees. The light source itself
must NOT appear in frame.

Subject: {ЗДАНИЕ}
Moving elements: {ЧТО ИМЕННО ДВИЖЕТСЯ}

BACKGROUND — CRITICAL: every pixel that is not the building must be flat
solid magenta #FF00FF, reaching all four edges and corners, identical in
every frame. No ground, no platform, no shadow cast onto the magenta,
no sky, no text, no watermark.

Duration 2 seconds, seamless loop.
```

### Что должно двигаться — по зданиям

| Здание | Движение |
|---|---|
| Завод, литейная, электростанция | дым из труб клубами вверх, отсветы огня в проёмах, вращение колеса/маховика |
| Мельница | водяное колесо вращается, вода стекает лопастями |
| Кузница | всполохи горна, искры, движение мехов |
| Вокзал | пар из-под навеса, семафор мигает |
| Космопорт | подсветка стартового стола пульсирует, пар из клапанов |
| Термоядерный реактор | тороид светится волнами, дуги разрядов |
| Дата-центр, ИИ-ядро | бегущие огни на панелях, пульсация схемного рисунка |
| Обсерватория | купол медленно проворачивается, телескоп смещается |
| Медиабашня | красный огонь на мачте мигает, рекламная панель переливается |
| Солнечные панели | блик медленно проходит по ряду |
| Рынок | полощутся полотнища навесов |
| Порт, верфь | лодка покачивается, вода бликует |
| Ферма | колосья колышутся волной |
| Кострище | пламя, угли, редкие искры |
| Замок, стены | знамя полощется на ветру |

### Люди и NPC — отдельная задача

Жители сейчас рисуются процедурно и на экране занимают ~6 пикселей. Прежде
чем заказывать им анимацию, **посмотри на масштаб**: на такой величине
проработанная модель не читается вовсе, и это будет выброшенная работа.

Разумный порядок:
1. Сперва увеличить видимый размер жителя в рендере и проверить, что город
   при этом не превращается в кашу.
2. Только потом заказывать спрайт-листы.

Если делать — формат такой: **4 ракурса** (вниз, вверх, вбок + зеркало) ×
**4 кадра ходьбы** + 2 кадра простоя. Отдельные листы на профессии, которые
визуально различимы: рабочий, лесоруб, шахтёр, фермер, инженер, жрец, солдат.
Одежда по эпохам — палитра уже задана в `app/src/render/palette.js`
(`VILLAGER_CLOTH`, 10 эпох).

Промт для персонажа — тот же шаблон, но:
`Subject: a {ПРОФЕССИЯ} of the {ЭПОХА} era, {ОДЕЖДА}, walking in place,
seen from a high three-quarter top-down angle. Moving elements: legs stride,
arms swing, tool bobs. The character stays centred and does not translate
across the frame.`

Требование «не смещается по кадру» здесь такое же важное, как у зданий:
позицию задаёт игра, а не анимация.

### Приёмка анимации

- Кадры одинакового размера, здание в них не «плавает».
- Петля бесшовная: последний кадр стыкуется с первым без рывка.
- Фон вырезается тем же `tools/art/cutout.mjs` без ручной правки.
- Вес спрайт-листа после упаковки — не больше, чем у 12 статичных кадров;
  если больше, режь число кадров, а не качество.

## 6-В. МЕХАНИКА ЗНАМЕНОСЦЕВ (заказ клиента)

Отдельный род войск, который не столько дерётся, сколько держит армию.

**Суть.** Знаменосец даёт всей армии прибавку к боевой силе. Его гибель —
не просто минус боец: мораль войска резко падает, и падение сохраняется до
конца боя. Знаменосец превращает потери из арифметики в событие.

**Что нужно заложить:**

1. **Воодушевление.** Пока знаменосец жив, вся армия получает прибавку к силе.
   Прибавка не должна складываться без предела: два знамени сильнее одного,
   но заметно меньше, чем вдвое — иначе оптимальной стратегией станет армия
   из одних знаменосцев.
2. **Потеря знамени.** Гибель знаменосца бьёт по морали сильнее, чем гибель
   любого другого бойца, и эффект держится до конца сражения. Восстановить
   мораль в том же бою нельзя — только вторым знаменем, если оно есть.
3. **Приоритетная цель.** ИИ противника должен понимать ценность знаменосца
   и целиться в него — иначе механика не создаёт напряжения. Но не абсолютно:
   знаменосец должен быть уязвим, а не обречён.
4. **Знамёна победы.** После выигранного сражения знаменосец **ставит знамя
   на месте битвы**. Это постоянная отметка на карте: она видна, она помнит,
   где и когда была одержана победа, и её можно осмотреть. Знамёна
   накапливаются и становятся летописью войн прямо на местности.
5. **Знамя как трофей.** Если бой проигран, знамя достаётся победителю.
   Трофейные знамёна вешаются на цитадели — видимая история побед над
   конкретной фракцией.

**Где это ложится на существующий код:**

- Роды войск и их сила — `UNITS` в `data.js`; контр-циклы — `COUNTERS`
  (сейчас в расчёте боя **не участвуют**, см. §4).
- Отряды на карте — модуль `app/src/core/systems/army.js`.
- Отметки на местности — `app/src/core/systems/worldsites.js` умеет ставить
  и хранить объекты на карте, знамёна ложатся туда же.
- Цвета фракций для знамён — `FACTIONS[].color` в `data.js`.
- Хроника побед — `s.chronicle`, надстраивается модулем `laws.js`.

**Чего не делать:** не превращать знаменосца в неубиваемого. Механика
интересна ровно тем, что знамя можно потерять.
