## 0. ГЛАВНОЕ ЗА ОДНУ МИНУТУ

**Что это.** «ФРОНТИР» — браузерная стратегия про развитие цивилизации от
первого костра до Шпиля, уходящего в звёзды. 10 эпох, 62 технологии,
58 зданий, 8 фракций-соседей с ИИ, дипломатия, рынок, рейды, события.

**Как запускается.** Двойной клик по `frontier.html`. Один файл, работает
офлайн по `file://`, без сети, сборщиков и фреймворков. На телефоне — тот же
файл, интерфейс сам переключается в мобильный режим.

**Чем НЕ является.** Это не Unity и не Unreal. Предыдущее ТЗ (№5) требовало
Unity-проект — решение было пересмотрено заказчиком в пользу браузера, потому
что браузерный билд запускается у заказчика прямо сейчас, а Unity-проект
потребовал бы установки движка и не мог быть проверен исполнением.
**Не переписывай на другой движок без прямого указания заказчика.**

**Язык.** Весь интерфейс, все тексты, все комментарии в коде — русские.
Английские строки в интерфейсе недопустимы.

## 1. КАК ЗАПУСКАТЬ И ПРОВЕРЯТЬ

```bash
# из корня репозитория

node app/tests/simtest.mjs      # 18 headless-тестов ядра. ВСЕ должны проходить.
node tools/build.mjs            # пересобрать frontier.html из app/ (esbuild)
node tools/shot.mjs             # скриншоты игры в настоящем Chromium + ловля ошибок консоли
node tools/shot.mjs town        # только один пресет
```

**Правило приёмки:** после любой правки прогоняй `simtest.mjs` и `shot.mjs`.
`shot.mjs` возвращает ненулевой код, если в консоли браузера есть хоть одна
красная ошибка. Ноль ошибок — обязательное условие.

`tools/shot.mjs` умеет строить настоящий город из 33 построек (`town`,
`town_night`, `town_phone`) — без этого на скриншотах пустая карта и оценить
отрисовку невозможно.

Мир задаётся сидом через адрес: `app/index.html#seed=4242`. Один сид — один
мир. Удобно и для игрока, и для повторения баг-репортов.

## 2. АРХИТЕКТУРА

```
app/
  index.html              разметка + CSS. Все id, к которым обращается код (их 47).
  src/
    core/                 ЯДРО. Чистый JS, никакого DOM. Тестируется в node.
      simulation.js       класс Simulation (~1900 строк): тик, экономика, жители,
                          армия, рейды, фракции, дипломатия, рынок, события, сейв
      data.js             ВСЕ таблицы: TILE, RES, ERAS, TECHS, BUILDINGS, UNITS,
                          COUNTERS, FACTIONS, DIPLO_FACTORS, WEATHER, EVENT_DEFS
      world.js            генерация мира, A*, stepToward, findNearestTile
      rng.js              детерминированный ГПСЧ + шум Перлина
      systems/            новые подсистемы улучшений (см. §5)
    render/               ОТРИСОВКА. Ядро о ней не знает.
      renderer.js         оркестратор кадра
      terrain.js          местность: рельефный свет, биомы, детали, берег
      sprites.js          процедурные спрайты построек, 22 архетипа силуэтов
      palette.js          цветовая библия: местность, эпохи, свет по времени суток
      quality.js          пресеты графики + автоподбор по FPS
      artpack.js          подмена процедурных спрайтов нарисованным артом
    ui/
      hud.js              весь DOM-интерфейс: панели, модалки, вкладки
      audio.js            WebAudio: синтезированные SFX + музыка
      assets.js           сгенерированные ассеты в data-URI (обложка, победа, тема)
    save/saveSystem.js    localStorage + экспорт/импорт файлом
  tests/simtest.mjs       18 headless-тестов
tools/
  build.mjs               сборка однофайлового frontier.html
  shot.mjs                скриншоты в Chromium + проверка консоли
  art/                    конвейер нарисованного арта (см. §6)
```

**Разделение слоёв железное:** ядро не знает про DOM и canvas. Это позволяет
гонять всю математику в node и держать 18 тестов. Не ломай это.

**Детерминизм.** Вся случайность идёт через `this.rng` (mulberry32 от сида).
`Math.random` в игровом коде запрещён: он ломает воспроизводимость мира и
сейвы. Это не стиль, а требование — есть тест на детерминизм.

## 4. ЧТО ЗАВЕДОМО НЕ РАБОТАЕТ (честный список)

Проверено по коду, не догадки:

- **Армия не рисуется на карте.** `renderer.js` не содержит ни одного
  упоминания UNITS. Армия — число во вкладке «Армия».
- **Контр-цикл родов войск не работает.** Таблица `COUNTERS` в `data.js`
  есть, в расчёте боя не участвует.
- **Интерфейса рынка нет.** Здание строится, описание обещает обмен, цель
  игры требует его возвести, курсы и караваны в ядре посчитаны — кнопки
  «продать» нет ни одной.
- **Аура кузницы «+10% соседям» не применяется**, приоритет труда «Стройка»
  ни на что не влияет.
- **Сейв теряет** мирные пакты, штрафы событий, кулдаун событий — возможен
  сейв-скам и потеря купленного мира.
- **Робозавод** (`workers: 0`) не производит ничего: отсекается проверкой
  `!def.workers`. Одно из самых дорогих зданий игры — декорация.
- **Погода у фермы умножается дважды**: дождь вместо +15% даёт −2%.
- **Кризис еды** при населении 57+ без амбаров становится вечным: порог
  `население × 0.7 × 5` превышает потолок склада 200.
- Нет экранов достижений и мировой карты (в мануале они есть — в игре нет).

## 6. АРТ: КОНВЕЙЕР И СОСТОЯНИЕ

Игра умеет рисовать здания двумя способами и **переключается автоматически**:
если для здания есть нарисованный спрайт — берётся он, если нет — рисуется
процедурно. Поэтому арт можно подвозить по частям.

```bash
node tools/art/gen-prompts.mjs   # пересобрать список промтов
node tools/art/cutout.mjs        # вырезать фон у art/raw/*.png → app/assets/sprites/
```

**Как устроено вырезание.** Генератор рисует объект на магентовом фоне
(`#FF00FF` — хромакей). `cutout.mjs` ищет фон **по тону**, а не по точному
цвету (генератор часто выдаёт малиновый градиент), удаляет только пиксели,
**связанные с краем кадра** (иначе вырезало бы розовые детали внутри самой
постройки), смягчает контур и обрезает по субъекту. Файлы, где в кадре
нарисованы трава/небо/солнце, помечаются как требующие перегенерации —
их нельзя «починить», нужно снять заново.

**Ловушка, на которой уже обожглись:** формулировка «single warm sun from the
top-left» заставляла модель рисовать **настоящее солнце в кадре**, а под
постройку подкладывать магентовый ромб на траве. В промтах это исправлено:
источник света явно запрещён в кадре, подставки перечислены поимённо.

**Состояние:** сгенерировано 41 изображение (все — здания), из них 15 новым
промтом. Осталось по приоритету 109. Приоритеты выставлены по тому, что игра
**реально отрисовывает**: 15 промтов помечены «генерировать не надо», потому
что применить их негде (юниты не рисуются, экранов достижений и мировой карты
не существует).

## 7. КАК РАБОТАТЬ ДАЛЬШЕ

1. **Читай код, прежде чем чинить.** Половина найденных багов выглядела как
   «фича не сделана», а оказалась «сделана и отключена одной строкой».
2. **Доказывай исполнением.** Ни одна правка не считается сделанной, пока не
   воспроизведён баг до и после. Пиши репро-скрипты, вставляй реальный вывод.
3. **Не верь тестам на слово.** Тест A* проходил и при 36 найденных маршрутах
   из 500, потому что ничего не проверял.
4. **Меряй, а не предполагай.** Три бага генерации мира нашлись замером
   реального размаха шума против порогов в коде.
5. **Не экономь на комментариях о причинах.** Комментарий «почему так» дороже
   комментария «что делает».
6. **Держи 18 тестов зелёными и консоль чистой.** Это приёмка.
